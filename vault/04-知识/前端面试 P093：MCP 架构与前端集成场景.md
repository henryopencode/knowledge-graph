## MCP 标准化哪一层

Model Context Protocol 为 AI 应用连接外部能力提供协议。可区分 host 应用、host 中的 client、提供能力的 server；模型参与生成意图或参数，实际连接、授权、调用和结果注入通常由宿主系统管理。

它不只是“模型直接连 USB”：工具、资源、提示等有不同协议语义，发现能力、协商、调用与错误处理也要有明确边界。

## 能与前端结合什么

- 开发工具获取项目文件、设计稿、接口文档等上下文，帮助生成或校验代码。
- 应用接入受控查询、可视化或业务操作，前端展示调用进度、参数、结果和错误。
- 把组件文档、设计系统、测试或构建等能力做成可复用服务，供多个兼容宿主使用。

MCP 并不保证任意 client 支持所有能力，也不自动解决文档准确性与业务数据模型。

## 纠正“协议本身自动安全”的理解

有结构化协议不等于权限已正确配置。调用方仍要管理身份、最小可用能力、参数校验和对有后果操作的用户意图；工具返回文本是数据，不应被当成可以覆盖用户请求的指令。

结果放入上下文通常不是重新训练模型权重。模型可利用新数据回答，不意味着它永久学习并保存了工具内容。

## 浏览器与后端分工

浏览器不适合持有长期服务密钥或直接暴露不受控文件、数据库能力。可通过自己的后端或具备正确授权边界的宿主接入，前端保留操作可见性和失败恢复路径。

面试项目应讲实际解决的问题、能力契约、调用链和验证结果，不能只说“接上 MCP 就变智能体、提高通过率”。
